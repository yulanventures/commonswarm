# People composition contract

Tom/HezLead authorized this expanded page composition on 2026-10-21. It supersedes the earlier People design contract's exclusions of profile details, role help and empty presentation for this worktree. The classic roster dialog and all authority behavior retain their existing owners.

The reference is the composition of `kylon-captures/17-members.png` and `18-agent-profile.png`: a compact roster in context, a selected profile in main, quiet type and a flat canvas. These are light desktop references, 1471×848. There is no captured dark or phone People reference. No reference code, artwork, assets, fonts or copy is incorporated.

Desktop has one searchable combined roster, native All/People/Agents filter buttons and a selected main profile or a calm selection prompt. People mode replaces the desktop workspace tree/mini-roster presentation. The actual rail, account, workspace menu, route hrefs and workspace switching remain; the page exposes the existing workspace overview as “Switch workspace.” The shell keeps its native drawer and the one actual account node.

The real roster node moves back into the route page at 52rem and below. A phone starts with the full-width roster. Selecting a person or agent shows the main profile and compact People heading; the roster body/footer are hidden while selected. Native Close or page Escape returns to the matching row. If a filter/query had removed that row, closing clears that filter/query so the real return target exists. The workspace drawer does not repeat the mini-roster.

One compact H1 says “People & agents”; workspace identity remains the shell's context identity. Static roles are a quiet subline. Invitation is the olive primary action, Add an agent is secondary. Agent row actions remain in a native details/summary disclosure with their original gates, data hooks, hrefs and callbacks. Role editing and person removal move into the selected main profile. Role definitions and irreversible-removal facts remain reachable through native “About roles & removal.” Search has one result status covering visible people, agents and pending invitations/keys. No health, permission, grant, delivery or success facts are invented.

The profile uses existing Inter at 20px/600 for its heading and wide, wrapping facts. Short destructive button labels retain the actual target in their accessible names and the original confirmation facts. The page's confirmation buttons wrap. Every actionable target is at least 44px; page controls use a 2px ring with 2px clearance, and forced colors retain a 3px system outline. Detail remains normal flow with a 6px scroll margin on focused controls, preserving the e3da scroll repair. The route owns profile scrolling; the context owns its own desktop scrolling.

The builder's model, `peopleDialogCanAct`, role options, pending-save identity, stable-code refusal handling, model editor, access/expiry/hosted facts, invitations and confirmation commit callbacks retain ownership. No auth, backend, protocol, CLI, MCP, provider, transport or session semantics change. Moving a permitted action never asserts new agent parity; existing parity limitations remain release-review concerns.

Before every page rerender and route teardown the shell returns the same roster to its page anchor. It preserves focused search/control nodes during relocation and attaches the responsive listener only while it owns a roster. Persistent detail and member/sign-in blocks retain the existing parking lifecycle. The real navigation focus owner targets the relocated visible/non-inert H1, or the selected profile H2 when requested. Selected-agent exceptions target the current main inline error; row-action exceptions target the corresponding current context row.

This is an authored source contract, not execution evidence. Root must prove native focus, clipping, source bindings, lifecycle, permissions/refusals and before/after appearance on the resulting source. Historical 453c/e3da/v5 evidence is not proof for this composition.
