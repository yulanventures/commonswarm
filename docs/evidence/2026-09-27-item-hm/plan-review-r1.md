## 1. Security

**A hosted tool call falls through to a human GoTrue session.** `read` authenticates only a bearer. `handle` takes `(request, requestId, setPhase)` and returns 401 when `bearer(request)` is null (`supabase/functions/read/index.ts:403-415`). A non-`swm_agt_` token is allowed only for `renewal_grants` and `pending_access`; every other resource is rejected before `getUser` (`supabase/functions/read/index.ts:440-447`). `command` does the same ladder: join credential only for seat registration, then `swm_join_`, then `swm_agt_`, and every other bearer is `auth.getUser` plus `auth.getClaims` and becomes `verifiedHuman` (`supabase/functions/command/index.ts:11857-11934`). The only in-process precedent builds a new `Request` with `authorization: Bearer …` and calls `handleRequest` (`supabase/functions/h0/forward.ts:159-174`). Lane 1’s required export is `handleRequest(request) { return handle(request); }`, which cannot carry `HostedSeatContext`. Lane 6 then tells the auth service to call command with the human GoTrue session. A new command kind is human-reachable on that ladder until something rejects it. `HUMAN_ONLY_COMMANDS` is a fixed set of today’s kinds (`src/protocol/workspace-commands.ts:406-423`). `claim_hosted_seat`, `open_hosted_mcp_check_batch`, and `ack_hosted_mcp_check_batch` are therefore person-level operations unless a later gate refuses a GoTrue bearer. That is the seat acting as the grant owner.

**Seat names are not serialized against existing principals.** The plan treats `UNIQUE (workspace_id, name)` at `supabase/migrations/20260723000001_p1_schema.sql:173` as live. Line 173 is an invitations index. The principal unique constraint is at line 181, and `supabase/migrations/20260906000020_agent_execution_sessions.sql:4-5` drops `agent_principals_workspace_id_name_key`. The live rule is an advisory lock plus an exact name match that includes revoked rows (`supabase/functions/command/index.ts:8152-8165`) and the same check in the reducer (`src/protocol/workspace-commands.ts:960-965`). `claim_hosted_seat` locks only the grant row. Its unique key is `(grant_id, workspace_id, name)`. A hosted claim and `create_agent_principal` can both pass and insert two principals with one workspace name. That is the failure mode called out in `src/cli.ts` around the `Wren` recipient.

**Consent CSRF is a test name, not a control.** `docs/design/SWARM-CLOUD.md:463` requires every web mutation to be CSRF-protected. The browser consent step ends in `authorize_hosted_mcp_grant`, which runs as the victim’s GoTrue session. The plan says that if the library calls the adapter outside that transaction, the design is not final, and it still marks the plan GO. Replay revocation of the family has the same gap.

**CIMD fetching is “wrapped,” so the library can still fetch.** The SSRF list (HTTPS, no redirects, resolve-then-pin, refuse non-public ranges, size and time limits) is the right policy. `oidc-provider` 9.12.2’s experimental CIMD client fetches on its own. ## 2. Invariants

Workspace grants, seats, handles, and check batches are specified to go through command events. Signals stay append-only: a batch stores signal ids, not signal bodies. Client grants on the new authority tables are revoked from `anon`, `authenticated`, and `swarm_read`. These parts do not:

- **One command addresses one workspace.** `resolveRoute` takes a single `body.workspace_id` and locks that stream (`supabase/functions/command/index.ts:3006-3042`, `5862-5870`). Idempotency is `(principal_kind, principal_id, command_id)` and `principal_kind` may only be `user` or `agent` (`supabase/migrations/20260723000001_p1_schema.sql:368-378`). A multi-workspace consent that “anchors” on the lexicographically first workspace stores one stream and cannot ledger a `hosted_grant` principal. The other workspaces’ events are a second write beside the reducer.
- **Authority time is `statement_timestamp()` / the reducer clock.** `SWARM-CLOUD.md:85` stamps events on server time inside the command transaction. The new tables default to `clock_timestamp()`, which moves during the transaction and is not the reducer input.
- **OAuth credential rows are a second writer in `swarm`.** `AGENTS.md:36-37` sends every backend state change through the command path. `swarm_oauth` inserts, updates, and deletes `swarm.oauth_artifacts` directly. `REVOKE ALL ON SCHEMA swarm FROM PUBLIC` (`supabase/migrations/20260723000001_p1_schema.sql:107`) means that role also has no `USAGE`, and the grant tables’ RLS policies are only `TO swarm_command`. The `GRANT SELECT` to `swarm_oauth` returns no rows. The box asked for a separate schema so this writer would not sit in the authority schema.

The pasted `swarm.wake_path_eligible_deliveries` replacement drops the live predicates (release cutoff, `ask`/`note`, later-delivery exclusion, `security_barrier`) and grants `SELECT` to `swarm_read` and `swarm_command`.
