# Submission worker rules

These are instructions for a later HezLead-assigned submission worker. This packet grants no browser or submission authorization to its documentation author. C6 is GO for Claude connector directory and ChatGPT apps once C3 is met; C4 is waived and legal pages are live. Admin issuance is not a prerequisite.

1. Read the applicable ANVIL_SETUP, workspace/repository AGENTS and the exact submission task. The permitted sign-in is **SSO in Tom's already signed-in Chrome**, through the specifically assigned browser/computer-use path. Never launch installed Chrome from a script, open a real profile with Playwright, or substitute a fresh headless login. If the task lacks this explicit browser authorization, stop and list that missing authorization.
2. Use the existing signed-in session and existing organization. **Never type a password, create a production account, or enter a new-account flow.** A password or inaccessible SSO requirement means stop and report the exact service, field and requested action to HezLead. Never read the keychain or Chrome password store.
3. **Never perform identity/organization verification (government ID or business documents). Never pay, upgrade a plan, accept a paid trial or add payment details.** Read existing OpenAI organization/project rights, identity and domain-verification status under Tom's existing SSO. Reading/copying the organization-generated DNS TXT challenge for `commonswarm.com` is allowed: record the exact name/value and status in [DNS-TXT](DNS-TXT.md), for the handoff at `~/work/cswarm-submissions/DNS-TXT.md`. HezLead adds it via the Cloudflare API; the worker does not change DNS or publish a challenge file. If OpenAI requires identity/organization verification and it is incomplete, park ChatGPT for Tom and submit Claude alone when its C3 items are met. Report any missing permission, subscription or verification requirement.
4. Use the directory's LISTING and PORTAL-FIELDS, and [REVIEWER-ACCESS](../2026-10-03-reviewer-packet/REVIEWER-ACCESS.md). The default reviewer path uses the reviewer's own identity-provider account and workspace. Do not create or populate an account on their behalf. HezLead ruling B authorizes submission with self-serve access plus the exact reviewer-notes sentence in both listings/portal maps and REVIEWER-ACCESS. CC-12/OA-10 are nonblocking; Tom's [morning identity/credential step](TOM-MORNING-REVIEWER.md) remains pending. Do not claim vendor acceptance or credentials already supplied.
5. Keep any Tom-approved reviewer credentials outside Git, screenshots, logs and chat. If a separate approved task stages secrets, use a fresh mode-0700 `mktemp -d /private/tmp/anvil-secret.XXXXXX` directory, mode-0600 files, service-account-token-file-only `op`, and guarded `rm` cleanup at the end. Do not retrieve secrets just to prepare a listing. No password entry is authorized by this rule.
6. Read every actual portal field, required marker and policy acknowledgment. Fill the documented values, mark unexpected unknowns **worker reads from portal** in the report, and do not claim an unperformed test or accepted scan. Never affirm all-tool execution until its redacted results exist. Use support@commonswarm.com for support/reviewer contacts; preserve security@commonswarm.com for vulnerabilities and legal@commonswarm.com for legal matters. Contact/SSO/code/account limitations must remain explicit in reviewer instructions.
7. Obtain existing all-tool receipts for each assigned vendor. For OpenAI, also obtain exactly five positive/three negative cases and an accessible actual recording. Resolve required package/code/support/setup findings. Do not submit while a C3 mandatory item is missing; do not add a new legal/admin/C6 decision gate.
8. Submit only the two assigned directory entries when C3 is met. Record timestamp, directory, selected existing organization/project, submitted draft/package version, status/reference, remaining findings and task-owned screenshots with secrets excluded. Publication and approval are separate outcomes; do not announce either without evidence and authorization.
9. If blocked, stop the dependent action and list precisely what Tom must do, the portal field/message, and whether the other submission can proceed. No GitHub Actions dispatch, production release, SSH/service restart, DNS change or other-directory work is part of this task.
