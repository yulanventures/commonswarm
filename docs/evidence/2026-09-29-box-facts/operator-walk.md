# Operator walk-through of HM37 and HM8 release plans

This is a local, read-only audit of the plans at cloud-swarm main
`beb93996166af94b60d08b5cb2433956cba28f28`. No release block, SSH command,
production command, GitHub Actions dispatch, or release window was run for this
audit. Secret values are intentionally omitted.

The walk used these P1 selections: `KIND_LIST=edge stack`,
`H0_LEDGER_BACKFILL=no`, `GUARDED_STACK_SWITCH=no`,
`BACKUP_STATUS_PROOF=no`, `API_CADDY_PAIR=no`, `MCP_CADDY_RELEASE=no`,
`CHANGED_FUNCTIONS=command mcp`, and `ROUTER_CHANGED=yes`. Prompt 184 also
established `BACKUP_MAX_AGE_SECONDS=86400`; it did not establish either window
time. The normal sequence and all defined tails were traced: pre-commit failure,
post-commit control failure, each S1-S5 rollback, abort before and inside Deno
installation, interrupted hosted control/lost shell, retry, rollback, copy-back,
and close. P2 has no Deno or S-class paths; its corresponding paths are not
applicable, but deployment failure/disconnect, rollback, browser recheck, and
closure were traced.

An item can appear in more than one kind when the defects are distinct: for
example, an unset path variable is K1 while the missing file at that path is K3.
Counts are findings, not the number of individual files inside a grouped bundle.
