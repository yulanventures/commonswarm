On the pinned image, a database marked `real-marker` reported `n-db-target-v1` when the connection used `options=-ccommonswarm.stack_identity=n-db-target-v1`. The same option made unmarked `template1` report the target marker. `make-pg-service.mjs:60` copies URL parameters into the service file. A URL aimed at `172.31.0.10` with that option and another database name passes the host check and the marker check. `apply-h0-upgrade.sh` or `pg_restore --clean` would then run there. The installed scripts do not add this option. `dump-database.sh:26` also clears `PGOPTIONS`, so the backup path does not have this hole.
